# 规格：百闻牌桌宠（给 Agent 的硬约束）

这份文档只写**已经实测确认**的事实和判据。没验过的写在「SKIP」里，别当结论用。

## 目标

在 Windows 桌面常驻一只会互动的百闻牌 Spine 桌宠：待机循环、单击/双击/滚轮/拖拽各触发不同动作、
闲置随机自我表演、入睡换姿态、整点报时。素材全部来自本机解包，渲染端复用 DeskSpine。

## 非目标

- 不做分发、不做商用、不上传任何素材或打包产物。
- 不去破 32 位资源名哈希来还原官方文件名——命名一律走「联系表 + 肉眼挑」。
- 不碰游戏进程、不联网交互、不改任何在线数据；素材是只读解包。
- 不做图鉴卡面（`deck` 组，297 个 `deck_idle`、1400×787 画布）的桌宠化，那批是卡面动画。
- **头像框不进桌宠**（2026-10-28 撤回）：这条当天先被移进目标、做完并看过桌面实测，用户随后拍板不要。
  撤的只是桌宠侧接入（配置框键、托盘菜单、装框脚本、`frame` 判据），10 张角色框素材和引擎层
  `FrameLayer`/`Silhouette` 都留着；接法和从游戏量出来的贴合规则记在「头像框图层」一节，日后要再接照那份走。

## 管线（每步都要留可核对的产物）

| 步骤 | 命令 | 产物 |
| --- | --- | --- |
| 解包 | `python npk_unpack.py <npk> t/<pkg>` | `t/<pkg>/` 逐条 zlib 解开，文本按**字节**写 |
| 包内文本 | `python npk_text.py <npk> t/<pkg>_text` | 只倒 xml/atlas/json/txt，查资源名用，不动纹理 |
| 纹理清单 | `python npk_scan.py <npk> out/<pkg>_scan.tsv` | 每条纹理 `idx kind off clen w h fmt`，**不解码**，用来筛要解哪几条 |
| 普查 | `bwp-probe census t/<pkg> out/<pkg>_census.tsv`（或 `dotnet run --project probe -- census ...`） | 每个骨架一行：状态/画布/动画名(第 18 列)/region 名 |
| atlas 配对 | `python atlas_index.py t/<pkg>` | `t/<pkg>/_atlas_index.json`，**按 atlas 序号**索引页纹理 |
| GUI 名册 | `python gui_plist_index.py t/gui_text out/gui_atlas.json` | plist → 页名 + 每个 region 的矩形（401 份 plist / 20008 个 region） |
| GUI 页配对 | `python gui_page_map.py npk/gui.npk out/gui_scan_all.tsv out/gui_atlas.json crops/gui_frames` | 按**资源名**裁出的 PNG + 每页的 fit 判决日志 |
| 归属打包 | `python avatar_models.py <pkg> <groups> [out]` | `t/<pkg>_<group>/<stem>/`：合并 atlas + 硬链接页 + `_models.tsv` `_frame.tsv` `_pages.tsv` |
| 渲染 | `bwp-render-wall <root> <out> [viewHeight] [seconds] [anims=all] [target]` | `<model>@<anim>.png`，读 `_frame.tsv` 按各自画布取景 |
| 联系表 | `python grid_sheet.py <thumbs> <root> <out>` / `wall_sheet.py` | 一人一行、一表情一列的挑素材图 |
| 装机 | `python setup_pet.py [skel]` | 编译 Release + 写 config + 启动 |

解包的硬规矩：
- **数据区要一直扫到文件尾**：0x14 那个看着像 `toc_start` 的字段**不能当数据区结尾用**。
  `gui.npk` 在它之后还压着 **67 块**（实测 carve 出来数：44 张 2048x2048 的 ASTC 4x4 atlas 页 + 16 PNG + 7 JPG，
  尾部约 192MB 是加密 TOC，`carve` 靠魔数+自校验，扫到 `len(d)` 只会多出十几次失败的 zlib 尝试）。
  原来按 toc_start 截断，这 67 块在**每一次解包里都是静音丢失**的。`npk_unpack.py`/`npk_scan.py` 现在都扫到 EOF。
  **只有 gui.npk 有这个坑**：对它自己之外的那 10 个包，把 `toc_start..EOF` 这段单独 carve 一遍，
  **块数全是 0**（那段就是 TOC 本身，最大的 `spine.npk` 也只有 106KB），所以 spine/卡面那批既有结论不用重跑。
- `texture2ddecoder` 对 ASTC/ETC **一律返回 BGRA**。必须用 `Image.frombytes('RGBA', (w,h), buf, 'raw', 'BGRA')`
  读；按 RGBA 读会把红蓝整通道互换，全库素材偏冷偏紫，且从图本身看不出来。
- ETC 的解码函数**只收 `(data, w, h)`**，ASTC 才要多传 block 尺寸——把 bpp 一起传给 ETC 直接 `TypeError`。
  内部格式 `0x9278`/`0x9279` = ETC2 RGBA8_EAC，`gui.npk` 的 atlas 页在用，早先 `ETC_FMTS` 没登记它，
  整页会被当「认不出的格式」跳过（也是静音丢失）。`0x93B0`=ASTC 4x4、`0x93B7`=ASTC 8x8。
- 自检指标（不需要游戏截图对照）：数亮肤像素（V>170）里 `R>G>B` 与 `B>G>R` 的比例。
  游戏自带的原生 PNG `t/loading` = 2.79×，解包正确的 `t/spine` = 3.52×、`t/card` = 2.78×、
  `t/cardsmall` = 2.9×、`t/spine1~3` = 1.94/3.33/2.65×；**比值小于 1 就是通道反了**。
  页面级比值低于头像/卡面是正常的——原始 atlas 里本来就装着大量冷色场景和特效件。
- dump 目录里可能留着**上一代解包器的产物**：早期版本输出 `NNNN_<hash>.png`，现在只输出 `NNNN.png`，
  旧文件不会被覆盖也没人引用，但会被 `t/<pkg>/*.png` 这种通配一把捞进渲染（`sheets/card` 就这么混进过
  2739 张反色卡面）。对全 dump 出图前先按 `*_*.png` 清一遍。

gui.npk 的命名规矩（头像框就靠这条，别再走肉眼猜）：
- 它的 TOC 是加密的（尾部 2953 个 zlib 候选 2908 个解不开），所以图片 blob **全都没有名字**。
  **不去破这个 TOC**；同一个包里带着 401 份 TexturePacker plist（`npk_text.py` 倒出来就是 `t/gui_text/NNNN.xml`），
  写了 `realTextureFileName` 和每个 region 的 rect，于是「无名页 × 有名 rect」可以配对出**资源名**。
- 配对判据不许用粗网格 IoU 下结论：2048 的密页并集几乎铺满，IoU 全是 0.9x，会把 `_activity0` 这种
  认领到不相干的页上。IoU 只用来**提名**（每张图留 TOP=10），判决用整分辨率的
  `content_fit = (1-溢出)(1-空格)`：内容跑到声明格子（放宽 5px，ASTC 4x4 会渗色）之外算溢出，
  声明了格子但格子里没图算空格；门槛 0.995，之后按 fit 从高到低**一对一贪心认领**（一页只许配一张图）。
- plist 里的两个坑：`textureRect` 为空的是 **alias**（675 个，没有自己的矩形，必须扔）；
  `textureRotated=true` 的 448 个在**页上占的是宽高互换的那块**（mask/inset 都要换回来），
  而裁出来该往哪个方向转回去**没验过**，所以 `gui_page_map.py` 对 rotated 的 region 直接跳过并打印，不猜。
- 页名**不唯一**（同一页被多个 plist 版本引用），所以 `out/gui_atlas.json` 用 xml 文件名当键，不用页名。


打包的硬规矩：
- 骨架归属**只按 region 名集合**（相等→最小覆盖集），不能按 npk 文件顺序猜配对（`_spine_index.json` 里那个
  `skel` 字段就是猜的，错的）。
- 同一套 region 名在包里出现 **>2 次**的骨架判为「认不出是谁」，直接跳过别硬打包
  （`001_fg` 那种 35 个 atlas 共用一个 region 名的件就是这么骗过配对的）。
- 页名会撞：spine.npk 有 80 个页名被多个 atlas 共用、146 个 atlas 因此丢失，所以索引必须按 atlas 序号。
- 交付给用户看的编号 = atlas 页 id，只通过带标签的联系表给。

## DeskSpine 侧硬约束

- 这批骨架**只能用 3.6 运行时**（版本全是 3.6.52，个别 3.6.47/48/53）。选 3.8 不报错但解析出 0 个动画，
  最后在 `DefaultAnimationName` 抛 `Sequence contains no elements`。
- 纹理是 **PMA（预乘 alpha）**，用设置面板的 PMA 勾选，不改代码。
- 配置在 `%LOCALAPPDATA%\DeskSpine\config.json`：`SpineVersion=0x0306`、`InteractMode=5`（BwpHero，我们自己加的）、
  `SkelPath0..9` 必须是**绝对路径**。开发版 Release 和装的 MSI 共用这个文件、共用同名 Mutex，只能跑一个。
- 程序保存配置是从内存反读的：某个模型加载失败会把用户刚填的路径**静默冲回旧值**。所以别让用户在 GUI 里
  按顺序点几下——直接读那个 json 看实际值，再一次性写对。
- `InteractMode=5` 旧安装版读到会抛 `NotImplementedException`。
- 战斗场景层过滤（`BwpHero.SceneLayers`）按**槽名前缀**生效：`beijing/qianjing/bj/bg` 隐藏、`guang` 压到 0.25。
  表情骨架里也有件会被命中（`buzhihuo_yihua_2717` 的 `guang`、另 9 个 emotion 包的 `beijing*/bj_*/bg_*`）。

## 动画角色映射（`TinyEngine/src/BwpAnimator.cs`）

两套词汇按动画名自动分流，**不硬编码具体骨架**：

- 命中表情词（`happy/sad/surprise/thinking/smile/angry/serious/emotion`，归一化后精确匹配）→ 表情映射：
  拖拽=`surprise`、单击=`happy`、双击/滚轮=`thinking`、登场/睡醒/报时=`surprise`、睡觉=`idle`、
  闲置随机=整个表情池。表情够多时四个交互不撞同一张脸；`emotion1..6` 这种无语义名按编号依次分配。
- 否则走式神立绘的五槽姿态映射：`idle1/battlestand/combat1/casting1/born_break`，
  带拼写变体容错（`bettlestand/cassting1/casbat1/idle`），缺哪个动作退化成同类动作。
- 归一化 = 抹掉数字和下划线（`idle1`→`idle`、`born_break`→`bornbreak`），所以**必须**用「命中表情词」而不是
  「有 idle」来判表情骨架；909 个式神骨架对表情词零命中，这是分流安全的前提。
- 归一化额外把 `suprise` 纠成 `surprise`：素材里唯一的拼错件（`maozhanggui_sp_yihua_3754`），不纠它进不了
  `MoodWords` 的门，那颗头只剩 happy/sad/thinking，拖拽和单击撞同一张脸。

## 多只切换（名册模式，`TinyEngine/src/SpineSlot.cs`）

- `SkelPath0..9` 有两种语义，由 `SpineConfig.ActiveSlot` 决定：
  `-1` = 图层模式（原始行为，所有槽位叠在同一位置一起画，碧蓝动态立绘那种一层层拼的素材靠它）；
  `>=0` = 名册模式，`Render`/`Update` 只放行那一格，槽位就成了「一只一格」的角色名册。
  默认 `-1`，所以老配置不动。
- 换人有两个入口：宠物身上 **Ctrl+滚轮**（`LayeredRenderWindow` 在派发 `Scroll` 之前拦，图层模式不拦，
  所以老素材的滚轮动作不受影响）；托盘右键 →「切换角色」，按已装载槽位现搭菜单，勾选的是出场那只，
  多于一只时末尾给「图层模式(全部槽位)」出口。
- **插菜单项必须写在 `ConfigForm` 构造函数里，不能写在 `ConfigForm_Load`**：`Program.Main` 只
  `new ConfigForm()` 从不 `Show`，Load 要等用户第一次打开设置窗口才触发，放 Load 里就是「托盘上没有切换角色」
  （踩过一次）。验证办法：反射构造 `ConfigForm`，读私有字段 `contextMenuStrip`，看「切换角色」在不在「设置」前面。
- 空槽位保护：`ActiveSlot` 指到没装载的格子会自动退到第一格已装载的；卸掉正在出场的那格同样挪位，
  避免桌宠直接隐形。切换时调 `animator.Reset()`，所以换人先播一遍登场再回待机。
- 缩放/位置/翻转/PMA 是 `SpineSlot` 全局的，换人不换尺寸——三只 Q 版头像都是 112×135 上下，够用。
- 菜单里的名字一律中文，由 `DeskSpine/src/PetNames.cs` 按骨架文件名（不含扩展名）查表：
  `buzhihuo_1127`→不知火、`qianji_0552`→千姬、`maozhanggui_sp_yihua_3754`→猫掌柜焕宴。
  表里没有的退回文件名（宁可土也不瞎猜）；`setup_pet.py` 的 `PET_NAMES` 是同一份对照，只影响控制台打印。
- 右键双击**不再**切 `WS_SIZEBOX`：透明窗口带上它就会在宠物周围露出一圈边框（用户报的「透明边框」），
  缩放走设置窗口的 Size/Scale，这个入口直接废掉。
- `setup_pet.py` 不带参数就把 `buzhihuo_1127 / maozhanggui_sp_yihua_3754 / qianji_0552` 写进槽位 0/1/2
  并置 `ActiveSlot=0`；给参数就按参数装名册。

## 头像框图层（`TinyEngine/src/FrameLayer.cs`：引擎层留着，桌宠没接）

- 一层贴图盖在宠物头上：`FrameLayer : Renderable` 注册在 `scene.Renderables` 里 `spineSlots` 之后、`speaker` 之前，
  所以框永远画在宠物上面。原计划叫 `PictureLayer`，实现时按用途定名 `FrameLayer`。
- **桌宠侧的接入 2026-10-28 已撤**：`SpineConfig.FramePath0..9`/`ActiveFrame`、托盘「头像框」菜单、
  `setup_pet.py` 装框、`bwp-animator-test frame` 判据都删了（`setup_pet.py` 还会顺手把现场配置里残留的框键清掉）。
  留着的是 `SpineRenderWindow.Frames` —— 名册空着时 `ActiveFrame` 恒为 -1，`Update` 第一行就跳过探针，
  不戴框不烧 CPU。**以后再接只动 DeskSpine 那侧**（把框名册长回配置和托盘），图层本身不用改。
- 框素材在两处：`crops/gui_charframe_canvas/`（归一到 128 画布的 10 张，规则要用的就是这批——
  贴边裁切版 `crops/gui_charframe/` 把装饰件裁掉了，画布版才是游戏里那个方框本身）和 `crops/gui_frames/`（117 张 UI 框，
  接之前也没接过）。量几何的两个脚本留着：`frame_canvas.py`（从 plist 归一 128 画布 + 出 `geometry.tsv`）、
  `frame_fit.py`（拿规则在静态渲染图上排联系表）。
- 位置和大小都不写死，跟着出场骨骼走：`Spine.WorldBounds`（新加的抽象属性，`Spine36/38` 各自实现）
  → `SpineSlot.ActiveWorldBounds`（图层模式把所有槽位并起来）→ `FrameLayer.TargetBox()`。
- **贴合规则照游戏自己的排布来，一框一宠都不调**（2026-10-28 重做，取代早先手挑的 `HeadRatio/HeadDrop`）：
  游戏把环画在 128×128 画布里，放头像的洞同心于画布（实测洞心离画布中心 ≤5px）、洞径占画布 0.52~0.57，
  洞开在**脸**上。桌宠这边就一条规则：环画布一比一顶替「画出来的那截身子」（`BoxOverHead=1`），
  洞心（`MeasureHole` 从框的 alpha 里量出来，直接当精灵 `Origin`）落在**量出来的头团心**上。
  包围盒不能直接当那个方框：`WorldBounds` 走的是整个图集矩形 region，而表情图集全是 `size==orig / offset:0,0`
  （900+ 个 atlas 零裁切），可打包出的 PNG 在 region 内还留着大片透明留白 —— 实测「画出来的高 / 包围盒高」
  = 0.867（不知火）/ 0.914（猫掌柜焕宴）/ 0.905（千姬），虚增全垫在下半身。
  所以 `FrameLayer.Probe()` 离屏拍一发 256²（视图 = 包围盒 ×1.2 留余量、Y 翻转），用 `Silhouette.OpaqueBox`
  量画出来的方框、`Silhouette.HeadMass` 量头团心，两个数一起喂给 `TargetBox()`；按 `ProbeEvery`(0.1 秒) 续量
  （呼吸和换表情会挪头，千姬实测头横向晃到 13 个世界单位），逐帧按 `1-exp(-delta*FollowSpeed)` 平滑跟过去，
  换角色时 `fitted=false` 直接落位，不要从上一只的位置飘过来。
- **头团 = 剪影上半截里最厚的那块实心圆盘**（两遍 chamfer 距离变换，权重 10/14，除以 10 就是像素半径）：
  不能取全图最大圆 —— 千姬胸口那坨半径 30 比头的 28 还厚，最大圆会量到胸口，环就滑到下巴底下；
  所以只在「画出来的方框」上面 `HeadBand`(0.6) 的范围内挑最厚的圆盘。发冠、飘带、猫耳这些细长件挤不进圆，
  天然被排除，这也是为什么不用认脸就能定位头。
- **`WorldBounds` 必须自己走 `DrawOrder`，不能用运行时的 `Skeleton.GetBounds`**：后者不看 alpha，把
  `beijing/qianjing/bj/bg` 这些被 `SlotAlphaScale` 压成透明的底板也算进包围盒。实测 `qianji_0552` 的左边界因此
  从 -42 被拽到 -64.9，环心比可见剪影中心偏 28px。现在按 `skeleton.A * slot.A * AlphaScaleOf(...) > 0` 过滤，
  和 `Draw` 的可见性判据一致。
- **渲染视图是 Y 翻转的**（`LayeredRenderWindow` 把 `view.Size` 的 Y 写成负），所以环要用居中的 `Origin` 配
  `Scale.Y = -h/texH`，否则上下颠倒。SFML.Net 2.6 没有 `Sprite.FlipY`（CS1061）。
- **手搓的 `target.Draw(VertexArray, new RenderStates{Texture=…})` 在这里画不出像素**（同样的调用在 `Spine36.Draw`
  里能用，是因为 `states` 由 SFML 传进来）。换成 `Sprite` + `target.Draw(sprite)` 才出东西。
- 无头量法（`frame` 判据已撤，法子在案）：同一姿态连拍「有框/无框」两张，差集才是框自己的像素；
  视图按包围盒开（边长 ×1.6），否则环和宠物都被裁掉一半，量不准。`new Image(w,h)` 不是可靠的透明黑画布，别拿它当比对基线。
