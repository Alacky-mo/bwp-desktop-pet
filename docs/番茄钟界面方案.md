# 番茄钟界面方案

> 2026-10-29 定稿。这份只管**界面和素材**，计时逻辑（`Pomodoro.cs` 那套状态机、双轨时钟）一行不动。
> 四条决策已由用户点头，列在下面 §0；「仿 0/9」也已经用户判过并定稿成套（§7）。

## 0. 已定的四条

1. **推翻两条旧结论**（依据见 §1）：允许 WinForms 浮窗；数字倒计时可行。
2. **倒计时浮窗默认贴宠物头顶**，跟着宠物走。
3. **设置主窗那页番茄钟搬空，只留预设**，细项挪进独立小窗。
4. **先出 0/9 的仿风格对比，用户判断**——已判：仿形可收、走暖族、不加斜笔，成套图落在 `out/focus_digits/warm/`（§7）。

## 1. 那两条旧结论为什么作废

| 旧结论 | 现在的依据 | 还剩什么限制 |
|---|---|---|
| 「不做 WinForms 浮窗」 | `Program.PerfMonitorForm` **本来就是**一个 WinForms 浮窗，`ConfigForm.cs:372-384` 直接 `Popup(location)` 弹它；`AboutForm.Designer.cs:130` 也开了 `TopMost = true`。做浮窗不是新发明，是照抄现场已有的两个 | 壁纸模式那条要单独处理，见 §4.1 |
| 「数字倒计时做不了：全项目没有字体文件，SFML 画字要 ttf」 | 这条把「SFML 画字」当成了「画字」。本机 `C:\Windows\Fonts` 实测有 `msyh.ttc` / `msyhbd.ttc` / `simhei.ttf`，WinForms/GDI 直接可用；浮窗既然走 WinForms，就不归 SFML 管了 | **SFML 侧仍然不画字**，宠物身上（SFML 画布内）不贴数字、不做进度环——那是渲染层的事，没变 |

一句话：数字只出现在 **WinForms 浮窗**里，宠物本体还是纯 SFML。旧结论里「宠物身上做 LCD 数字/进度环」那部分**依然做不到，依然别提**。

## 2. 手势占用（实测，决定入口挂哪）

| 手势 | 现状 | 出处 |
|---|---|---|
| 左键单击 | 播攻击（睡着时播入场） | `BwpAnimator.cs:245-259` |
| 左键双击 | 播施法 | `BwpAnimator.cs:261-274` |
| 滚轮 | 播施法 | `BwpAnimator.cs:276-288` |
| 按住拖（左/右都算） | 进 `State.Dragging`，播 Alert | `BwpAnimator.cs:290`、`Animator.cs:236` |
| **右键拖动** | **移动宠物位置**（已占用） | `SpineSlot.cs:325-331` |
| **右键单击** | **什么都不做** —— `Click(Right)` 第一行就 `return` | `BwpAnimator.cs:248` |

所以入口挂**右键单击**，和用户的判断一致。注意别和右键拖动抢：按下到抬起之间位移超过阈值就得当拖动、不开窗（现场已有 `DragBegin` 可以判）。

托盘入口**保留**，两处进同一个小窗，文案一致（§5）。

> **P2 的改道（2026-10-30）**：P1 那版把右键单击**暂借**给了倒计时浮窗（`FocusFloatForm.ToggleWanted`），因为那时小窗还没影。
> 现在按本节原本的裁定还回去——**右键单击开预设小窗**；浮窗不再由手势开关，改成计时中就自己露、整窗点一下把**当前这一段**收起来

> 露收规则在 `FocusFloatForm.NextVisible`，六个 case 由 `desk` 的「右键分流 / 浮窗露收规则」那条钉住。

## 3. 素材：库里有什么、缺什么

### 3.1 数字（唯一需要仿的一层）

`gui/ui/autochess/img_num_1..8`，都在图集页 `_autochess0.png`（blob#5835，配得 100% 严丝合缝）。实测：

- 画布 63x106 ~ 88x106；**墨迹高 84~103 px**，十个字的中位 98、极差 15 px（**15% 的忽大忽小是真素材自带的**，不是仿出来的）。
- **分量 = 墨像素 / 墨迹高 = 31.3~48.8，中位 43.0**（最瘦的是 1，最胖的是 4）。这是「像不像同一只手写的」那把尺。
  > ⚠ 这条是返工返出来的。一开始用的是「横向切一笔的中位宽 / 墨高」（0.049~0.145，中位 0.112），**对 0 和 9 这种环形的字是错的**：
  > 一刀切过环会切到两条边，量出来和实心的 8 一样粗，画出来却是空心铁丝；照它追细还会把 9 蚀成三段。
  > 除以**外接框**也不行（0 天生填满框、1 天生空）。墨量除以**墨高**才跨字可比。
- **1..4 是暖族**：实心 `#fefbee`、描边 `#201000`/`#603000`（带棕）。
- **5..8 是冷族**：实心 `#ffffff`、描边 `#000010`/`#201040`（带蓝紫）。
- **库里没有 0 和 9**：全图集 39 个带 `num`/`digit` 的区域全是背景板（`img_num_bg`、`bg_num` 之流），没有一个字形；按「只差一个数字后缀」找齐 0..9 的一组，`autochess` 那组就到 8 为止。
- 真 1..8 身上本来就有碎点/飞白（实测连通块 1~6 块，6 头顶那一小条竖钉就是它自己的），**别当成仿图的瑕疵去修**。

> ⚠ 暖冷那件事是这次量出来才发现的：**现成的 1..8 不是一套色温**。直接混排，「25:09」里的 2 是米白、5 是冷白，眼睛看得出花。所以 §7 的表里除了仿的 0/9，还多给了两行「整套统一染成暖族 / 冷族」。

## 4. 两块界面

### 4.1 倒计时浮窗（专注时常驻）

- **默认贴宠物头顶**：位置 = 宠物窗口矩形上沿居中，跟着 `SpineWindow.Position` 走；宠物被拖、被缩放（`SizeX/Y`、`SpineScale`）都要跟。
- 载体：WinForms 无边框分层窗（照 `PerfMonitorForm` 那套），**不用 SFML**，所以能直接用 GDI 画字和贴图。
- 内容：`mm:ss` 大字 + 当前段名（专注/短休/长假）+ 一个 × 或整窗点击穿透（可配）。
- **底用 `bg_kuang02`（白色空心圆角框）九宫格拉成横条**，不用 `img_bubble_02`：那颗上下两条边斜着收尖，拉了就坏（§3.4 第 6 条）。
  `bg_kuang02` 实测从 28 px 拉到 420x150，圆角还是 3 px、线宽还是那道细边。
  代价是九宫格得在 GDI+ 里自己实现（P1）。
- 节拍：复用 `ConfigForm.cs:33` 已有的 `focusTimer`（1000ms）。**注意**：这个 tick 挂在 ConfigForm 上，而 ConfigForm 从启动就活着（`Program.cs:61` 建、`Application.Run()` 不退出），所以浮窗订阅它就行，别另起一个定时器——两处节拍迟早漂。
- 段的识别用 `focus.TransitionId`（`ConfigForm.cs:616` 已经在用它去重），浮窗照同样的办法判「换段了」。
- **壁纸模式是个坑，必须单独处理**：平时宠物窗是 `HWND_TOPMOST`（`LayeredRenderWindow.cs:125`），而壁纸模式会把它挂进 `WorkerW`（`LayeredRenderWindow.cs:293-329`）沉到桌面底下。这时一个 TOPMOST 的浮窗会**留在最上层、和宠物脱节**。方案：壁纸模式下浮窗跟着隐藏，或者同样降级——这条要实测，不能纸上定。

**P1 落地状态（2026-10-29）**

- 锚点那条链全在引擎里算：`LayeredRenderWindow.WorldToPixel`（世界框 → 窗口像素，视图 `Size.Y` 是负的，世界里最高的边落到像素小 y）→ `PetGeometry.HeadAnchor`（+窗口左上角 = 屏幕坐标）→ `FocusArt.HeadBounds`（水平居中、下沿离头顶 6 px、越界夹回工作区）。
  `DeskSpine` 侧只接数，不在 UI 线程碰 SFML 对象。
- **快照只在「窗口位置/大小变了」和显式 `RefreshGeometry()` 时重算**，所以骨骼呼吸那几像素的起伏浮窗不跟（1 秒一次也看不出）；
  装载完骨骼（`InitFromConfig`）、点应用/确认（`CurrentConfig` setter）、切换角色（`SwitchPet`）三处都补了 `RefreshGeometry()`，
  否则换了角色还照上一只的头摆。这三处补没补，只有桌面复验看得出。
- 透明走 `UpdateLayeredWindow` 逐像素（`Format32bppPArgb` + `AC_SRC_ALPHA`），**不碰 `Opacity`/`TransparencyKey`**：
  那张面板是「实心深底 + 圆角外透明」，颜色键模式做不到，和 ULW 混用行为没定义。
- 壁纸模式和整窗隐藏 → `OnFocusTick(focus, stowed: true)`，浮窗一起收走（上面那条坑按「跟着隐藏」结的，降级方案没做）。
- 走字用 `(int)TotalMinutes` 不是 `ToString(@"mm\:ss")`：后者是「分」这一位（0..59），时长上限给到 180，两小时会读成 `00:00`。托盘/气泡同一处改的。
- 数字条缺任何一个字就整行退回系统字体，不画一半缺一半（`FocusArt.DigitStrip` 返回 null 那条路）。

**2026-10-31 探针量到的两件事**（`bwp-assets/probe-jitter.ps1` / `hitmap.ps1`，DPI-aware，打的全是**物理像素**）

- **浮窗每秒左右呼吸 206~213 px**：宠物完全静止时 12 秒记到 9 次「跳」，**中心钉在 2361.5 一毫米没动、Δy 全程 0**。
  根因是倒计时那排数字**不是等宽的**（`1` 20 px、`4` 28 px 一档），每秒换字 → 内容宽变 →
  浮窗按头顶居中重摆 → 两边各挪 1~3 px。要治得给数字条固定内容宽（预留最宽那一档，或每字占等宽位），
  等用户拍板（复验单 R5 选项 d）。**冻住的倒计时不呼吸**（20 秒复测 0 次）—— 只有真走字时成立。
- **这些分层窗没有按 DPI 放大**：浮窗实测 **213x54 物理**（这台机器 200%）。
  旁证：`DeskSpine.csproj:11` 声明了 `PerMonitor`，而 `FocusFloatForm` / `FocusPresetForm` / `PerfMonitorForm` 里
  **搜不到一处 `AutoScale`/`Dpi`** —— 手写窗不指定 `AutoScaleMode` 就是不缩，画多少物理像素就是多大。
  **已实测**：面板量到 `276x406 物理 @ 1927,1056`，正好等于 `Arrange` 那套数（= 逻辑 138x203），推算成立。
  放大几倍属复验单 R6 第 13 问，等用户答。

**同一轮把「摆位跟当前姿势包围盒」这条旧裁定也结了（交接报告 §8 第 3 条）—— 那句写过头了**

### 4.3 主设置窗搬空

> ⚠ 搬空的时候必须防现场那个 bug 的同类：`ConfigForm.Value` 的 getter 是 `new Config()` 再把每个控件的值灌回去（`ConfigForm.cs:117`），**任何被搬掉控件、又没在别处回灌的键，点一次「应用」就被默认值顶掉**。上次「图层模式」就是这么中的（`SpineConfig.ActiveSlot`）。所以搬之前要先跑一遍「哪些键没了控件」的判据，再决定每个键是回灌还是删掉。

**竞品调研回来的一条印证（2026-10-30，全文见 `docs/番茄钟竞品调研.md`）**：细项进小窗、纯点击 −/＋ 这条路**站得住**——
有一定用户量的竞品全部开放逐分钟或至少逐 5 分钟编辑（Pomotroid、TomatoBar、FocusTimer、YAPA、Catime 点 dock 改值、
pomodorotimer.online、Pomofocus），**只给档位的都是极小或已归档的项目**（Samaya 5★ 镜像、`pom` 140★），
没有任何一个竞品把「三档预设」当成唯一的编辑面。所以要守住的不是「删掉编辑」，而是两条：
① **三档仍是首屏**（一次点击就开跑），细项是二级、不是入口；
② 纯点击从 25 按到 45 要 20 下，**补一个长按连发（约 400 ms 后每 120 ms ±1）+ 双击归位**当速度补丁
（`NOACTIVATE` 下 pressed 帧得自己画，而且这手势没有可发现性——所以它只能是补丁）。

> 现场另核出一条待决：`TinyEngine/src/Pomodoro.cs:205-222` 的 `Advance` 是 Working→休→Working **无限连轴**，
> 只有 `Abort` 能停 —— 竞品（YAPA）把「自动开始下一段」做成开关，我们把它写死了。要不要给「做完一个番茄就停住等我点」，

- **基类的建窗流程里不许读派生类构造体里才赋值的字段**。踩过一次（2026-10-30，就是 P2 之后那次启动卡死）：
  `LayeredRenderWindow` 的构造把 `CreateWindow()` 丢到渲染线程、自己在 `windowCreatedEvent.WaitOne()` 上等，
  而 P1 在 `CreateWindow()` 末尾加了那句 `_ = CurrentGeometry()` 去取「初始几何」—— 它调的 `AnchorWorldBounds` 是虚属性，
  `SpineRenderWindow` 的实现读 `spineSlots`，可那一刻派生类构造体一行都还没跑，字段是 null。
  NRE 抛进 `Task.Run` 那条没人观察的线程里，**既不弹窗也不退出进程**，只是 `Set()` 永远不执行 → UI 线程永远等 →
  没桌宠、没托盘图标、config.json 的 mtime 停在旧值（自动保存那颗 timer 还没开），而进程活着，所以第二次启动只看到「程序已在运行」。
  改成 `spineSlots?.ActiveWorldBounds ?? default` 就对了：空包围盒本来就是设计里有的状态，`HeadAnchor` 会退到窗口上沿居中。
  **这条纯函数判据抓不到，所以 `desk` 第 14 条真建一扇窗口。**
- **「算出该摆在哪」和「贴上了没有」是两件事**（2026-10-30，右键没反应那次栽的两个跟头，都在浮窗和小窗共用的那一层）：
  1. `LayeredPaint` 里 `UpdateLayeredWindow` 的 P/Invoke 把最后三个参数写成了 `ref BLENDFUNCTION, uint crKey, uint dwFlags`，
     Win32 的表是 `crKey, pblend, dwFlags`。参数个数没错、类型都在，编译器和 `desk` 前 14 条谁都不拦，
     于是每次贴图都在拿一个空指针当混合结构 → API 一律返回 `false` → **图、bounds 全对，屏幕上一个像素都没有**，
     窗口停在构造时那个 300x300。第 15 条就是为这条准备的：真贴一次，再问 Win32 窗口现在多大。
  2. `FocusPresetForm.Apply` 拿 `WindowPosition + WindowSize` 当「宠物」喂给 `SideBounds`，而宠物窗口本来就整扇铺满屏幕，
     左右两头都放不下 276 宽的面板，`SideBounds` 就把它夹到 `(0,0)` —— 小窗其实贴出来了，只是蹲在屏幕左上角。
     现在喂 `FocusArt.PetScreenRect(窗口左上角, 窗口尺寸, 骨骼包围盒)`：包围盒是窗口内像素，加窗口原点才落到屏幕上；
     包围盒还没装载就退成头顶那一个点。浮窗那边不受这条影响，它读的本来就是 `HeadAnchor`。
- **注入鼠标点击的三个坑**（桌面抓不了屏时唯一的自证手段，脚本是 `bwp-assets/click-at.ps1`）：
  `INPUT` 那四个字节 `type` 鼠标事件必须是 **0**，写成 1 就成了键盘事件，SendInput 返回「发了 2 个」而什么都不点——
  我第一次就是这么把「右键没反应」误判成事件链断了；PowerShell 5.1 不认 DPI，动手前先
  `SetProcessDpiAwarenessContext(-4)`，否则 2560 宽读成 1280、点到的位置差一半；
  移完先用 `GetCursorPos` 回读确认落在目标 2 px 内再点。点下去没反应时拿 `WindowFromPoint` 问一句「这一下到底落在哪扇窗」，
  比给自家代码加打印更快定位到「根本没送到」。
